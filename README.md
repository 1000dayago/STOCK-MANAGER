# 주식 관리 (HTML 앱)

분할매수 순번별 손익·평단가·배당·차트·시뮬레이션(백테스트)을 PC/모바일에서 쓰는 순수 HTML/JS 앱입니다. 빌드 과정이 없고 GitHub Pages로 그대로 배포됩니다. 데이터는 이 기기(브라우저)에 저장되고, 원하면 Firebase로 기기 간 동기화합니다.

## 기능
- **홈**: 자산 요약, 종목 카드(순번 요약), 현재가 한 번에 입력, 다가오는 일정, 최근 매매, 종목 비중, **자동 수집 상태 경고**(수집 실패·오래됨·수집 대상 반영 필요)
- **종목**: 종목마다 매수 순번(1번, 2번…) 기록·수정·삭제·분할/병합, 전체 평단·순번별 수익률, 해외주식은 매수/매도 환율 반영, 액면분할 조정
  - **차트**: 캔들(바로 아래 날짜 줄, 그 아래로 수급·거래량) + 볼린저밴드 + 이동평균(기간 설정) + 평단가선 + 최고·최저 표시 + 매수 순번 표시(파란 B 원, 아래에 순번)와 매도 기록 표시(S 원, 손익률), **외국인·기관·개인 수급(일별 막대 + 누적선)**, 거래량(+이동평균), **영업이익(분기 실적, DART)**: 기본은 **선그래프**(정기공시 **공시일** 위치의 점을 잇고, 직선/계단형 선택)이고 **표**로 바꿔 분기별 매출·영업이익·전년비·이익률·순이익을 볼 수도 있습니다(차트 아래에서 선그래프/표/끄기 전환). 전년 동기 대비 증가율과 흑자전환/적자전환을 표시하고, 맨 아래 **증감 패널**은 전년 동기 대비 **영업이익 증감액·부채 증감액**(억원)을 모든 분기에서 선으로 이어 보여 줍니다(“0 맞춘 분리” 기본: 두 선의 0 높이를 같게 하고 영업이익은 왼쪽·부채는 오른쪽 눈금, “같은 눈금”: 실제 크기 비교). 표에는 증감·부채·부채 증감·부채비율(부채÷자본)도 나옵니다. 캔들 아래 삼각형이 공시일, 십자선에는 그 날짜까지 공시된 실적만 표시합니다. 일·주·월봉, 3개월~전체, 드래그 이동·핀치/휠 확대·탭(마우스 올리기) 십자선 값, 전체 화면
  - **차트 이슈 표시·조작**: 유상증자(유)·무상증자(무)·감자(감)·분할/병합(분)·합병/분할(합)·CB/BW(CB)를 DART 주요사항보고에서 수집해 캔들 아래 글자 상자로 표시(십자선을 올리면 이름·날짜), 가격에서 감지한 액면분할도 표시. 십자선은 위쪽 손잡이(터치는 선 근처)를 끌어 원하는 날짜로 옮길 수 있습니다. 시뮬레이션에서 **누적 손익 곡선을 누르거나 끌면** 차트가 그 날짜로, **사이클을 누르면** 그 구간으로 이동하고, 차트의 **B·S 원을 누르면** 그 사이클이 펼쳐지며 해당 매수(또는 전량 매도) 줄이 강조됩니다.
  - **배당 기록**: 수령일·세전 금액·세금(국내 15.4%·해외 15% 자동 제안)·환율, 누적/연도별 합계, 손익 화면의 “실현손익 + 배당”
  - 매도/시뮬레이션(순번 선택, 선입선출·고가순·저가순·평단 비례 비교, 수수료·세금 자동 계산), 일정(실적·배당·주총), 바로가기 링크
  - **매매 사유 에디터**: 순번·매도 기록·종목마다 글쓰기(서식·표·사진), 매매 일지로 복기
  - 종목 추가·수정에서 **이름·초성으로 검색해 코드 자동 입력**(코스피·코스닥 주식·ETF·ETN)
- **손익**: 월별·연도별·종목별·기간 합계, 배당 합계, 해외 양도세 추정, 평가손익. **현재가는 자동 수집 종목이면 마지막 종가로 자동 반영**(직접 입력이 더 최신이면 유지)
- **계산기**: 평단가 계산, 목표 평단 역산, 손익분기 매도가
- **시뮬레이션**(백테스트): 수집된 시세·수급을 복사 없이 바로 선택(“○○ · 자동 수집”), CSV 불러오기(열 자동 인식·KRX 기관 합산·주/원 단위), 조건 자유 조합(거래량·이동평균·볼린저·RSI·MACD·신고가·등락률·렌코·분할매수·트레일링·**외국인/기관 수급**), **시뮬레이션 화면은 ① 종목·기간 → ② 전략 → 실행 → ③ 결과 순서의 아이폰 스타일 화면**(결과는 차트가 맨 위)이고, 고급 설정·데이터 불러오기·전략 저장은 접어 둡니다. 매수 조건은 연한 분홍, 매도 조건은 연한 하늘색으로 구분하고, **직접 조건 만들기는 문장 빌더**(조건 칩을 AND/OR로 이어 붙이고 괄호로 묶어 우선순위 지정, 칩을 눌러 값 수정, 문장 풀이와 **신호 진단**: 조건식이 참인 날 수·조건별 일수·겹치지 않는 AND 경고)이고, 조건은 한 줄 요약으로 모아 보이며 눌러서 값을 고치고, 추가는 아래에서 올라오는 선택창에서 분류별로 고릅니다. **매수 신호 선택·추세 조건·가격 조건(이평선 아래·RSI 낮음·볼린저 하단)**(이동평균선이 상승 중일 때만 매수 가능; 신호는 하락 시 / 외국인·기관 동시 순매수 + 거래량이 전일보다 높을 때 / 둘 다), **구간 재생**(접이식 메뉴: 날짜를 넣어 재생하거나 “재생 구간 지정”으로 전체 내비게이션 막대의 S·E 손잡이를 끌거나 차트에서 날짜를 골라 S·E 지정, 선택 구간은 차트에 음영·깃발로 표시하고 취소하면 사라짐, 재생 중에도 S·E 수정 가능. 차트의 **구간 확대**: 켜고 오른쪽→왼쪽 드래그로 그 구간 확대, 왼쪽→오른쪽으로 원래 화면(Shift+드래그도 가능). 고른 구간을 일·주·월봉으로 한 봉씩 움직이며 매수·매도·평단·보유 상태를 실시간처럼 표시, 배속·일시정지·슬라이더), **배수 분할매수(물타기) 전략**(10주 → 하락하면 20주 → 40주…, 매도는 평단 대비 목표 수익 또는 이동평균 데드크로스(예: 5일선이 15일선 아래로, 30일선이 하락 중일 때만 매도 선택 가능)에서 전량 매도 후 재시작)과 **사이클 분석**(청산까지 쓴 매수 횟수·돈·수량의 평균·최대와 횟수 분포, 사이클 줄을 누르면 매수별 평단·누적 투입금, 사이클 줄을 누르면 매수마다의 평단·목표가·평가손익이 펼쳐짐), 결과 차트는 종목 차트와 같은 기능에 사이클 구간 띠·평단·목표가선·매수 표시(1, 1-2…)·전량 매도 표시를 더한 것, **안전장치**(하락 추세에서 매수 중단·손절·최대 매수 횟수·최대 투입금 기본 켬, 청산 뒤 쉬는 날·매수 최소 간격 선택), 조건마다 **N일 이내** 옵션(사건형 조건을 AND로 묶을 때), **종목 일괄 비교**(모든 데이터에 같은 전략을 돌려 이익 종목 수·수익률 중앙값·앞 70%/뒤 30% 분할 결과·단순 보유 비교), 전략 저장·비교, 기간 분할 검증, 가상 매매 vs 백테스트 비교, 데이터 정보 카드
- **관심 종목 · 가상 매매 · 분할 매수 계획**: 목표 매수가, 실제 계좌와 분리된 가상 매수/매도(사전 기록/사후 입력 구분), 단계별 평단 계산
- **설정**(탭): 기본 설정(수수료·세금·환율·색상·링크 열기) / 자동 수집 / 동기화·백업 / 앱 정보
- Firebase 동기화(Google/이메일 로그인) + JSON 백업, 버전 확인·업데이트

## 화면 구성
휴대폰: 하단 메뉴 / 태블릿: 좁은 사이드바 / PC(1000px 이상): 펼친 사이드바. 소메뉴는 밑줄 탭, 카드 안 소제목은 얇은 실선으로 구분하고, 선택지가 적은 입력은 드롭다운 대신 버튼으로 보여 줍니다.

## 자동 수집 (국내 종목)
GitHub Actions가 평일 저녁 7시(한국시간)에 `tools/collect.js`를 실행해 `data/`에 저장하고, 앱이 그 파일을 읽습니다. 자세한 형식은 `data/README.md`.

| 자료 | 출처 | 키 |
|---|---|---|
| 일봉 시세(시·고·저·종·거래량) | 공공데이터포털 키가 있으면 그것, 없으면 네이버 모바일 증권(비공식) | 선택 |
| 외국인·기관·개인 순매수(주) | 네이버 모바일 증권(비공식) | 불필요 |
| 공시·재무(분기 영업이익·부채·자본·공시일)·이슈(증자·감자 등) | DART | `DART_API_KEY` |
| 뉴스 | 네이버 검색 API | `NAVER_CLIENT_ID`/`NAVER_CLIENT_SECRET` |
| 종목 검색 목록(`stocks.json`) | 네이버 모바일 증권(비공식), 매주 갱신 | 불필요 |

- **수집 기간**: 설정 › 자동 수집에서 “최근 몇 년(1~15)” 또는 시작일~종료일을 정합니다. 처음 수집이 기간을 채우고, 이후에는 마지막 날짜 근처부터 이어 받습니다(쉬어도 비지 않음).
- **수집 대상 반영**: 앱에서 종목을 추가한 뒤 설정 › 자동 수집의 **수집 대상 반영** 버튼 → GitHub 이슈 화면에서 초록색 **Create** 한 번. 토큰 없이 `watchlist.json`이 갱신되고 수집이 바로 실행됩니다(저장소 소유자가 연 이슈만 처리).
- 키는 저장소 Settings › Secrets and variables › Actions에만 넣으세요(채팅·코드에 넣지 마세요).
- **저장소가 공개이면 수집 대상 목록(종목코드·이름)과 수집 결과는 누구에게나 보입니다.** 수량·매입가·매매 기록은 올라가지 않습니다.
- 네이버 주소는 **비공식**이라 형식이 바뀌면 해당 항목만 실패로 기록됩니다(기존 파일·다른 수집은 유지). 수집 시세는 수정주가가 아니라서, **액면분할·병합은 앱이 자동으로 감지해 그 이전 가격·거래량·수급(주)을 현재 기준으로 보정**합니다(가격제한폭 ±30%를 벗어난 하루 변동을 분할 비율에 맞춰 판단, 데이터 정보에 보정 내역 표시). 배당·유상증자로 인한 작은 가격 조정은 보정하지 않습니다.

## 링크 열기 방식
설정 › 기본 설정 › 종목 바로가기 링크에서 **새 창 / 기본 브라우저(안드로이드) / 앱 안에서 보기**를 고를 수 있고, 링크마다 따로 정할 수도 있습니다.

## 배포 (GitHub Pages)
1. 이 폴더의 파일을 공개 저장소에 올립니다.
2. 저장소 Settings → Pages → Source: `main` 브랜치, `/ (root)`.
3. `https://아이디.github.io/저장소이름/` 주소로 접속 → 휴대폰은 “홈 화면에 추가”.

## Firebase 준비
앱의 **설정 › 동기화·백업**에 “Firebase 준비 방법”이 있습니다. 요약: Authentication(Google, 이메일/비밀번호) 사용 → 승인된 도메인에 `아이디.github.io` 추가 → Firestore 생성 → `firestore.rules` 내용을 규칙에 게시 → 웹 앱 `firebaseConfig`를 앱에 붙여 넣기. **규칙을 게시하지 않으면 데이터가 보호되지 않습니다.**

## 개발/테스트
```bash
node tests/test.js           # 계산·검색·차트 계산 등 로직 테스트
node tests/collect.test.js   # 수집기·목록 도구 테스트(가짜 API 응답)
node tests/e2e.js            # 브라우저 통합 테스트(Playwright 필요: npm i -D playwright && npx playwright install chromium)
python3 -m http.server 8765  # 로컬 실행 후 http://localhost:8765
```
`tests/e2e.js`는 자체 서버를 띄우고 가짜 `data/` 응답을 쓰므로 네트워크·키가 필요 없고 저장소 파일을 바꾸지 않습니다. Playwright가 없으면 건너뜁니다.

### 파일 구성
`core.js`(계산·상태) · `backtest.js`(불러오기·지표·엔진) · `chart-stock.js`(종목 차트) · `charts.js`(막대·선·시뮬 차트) · `ui*.js`(화면) · `data.js`(수집 자료 읽기·종목 검색) · `sync.js`(Firebase) · `tools/`(수집·목록·버전 도구) · `.github/workflows/`(자동 수집·종목 목록·수집 대상 반영)

## 버전과 업데이트
- 설정 › 앱 정보와 홈 아래에 현재 버전이 표시되고, **업데이트 확인**으로 최신 여부를 확인합니다. 앱을 열 때와 앱으로 돌아올 때도 6시간마다 자동으로 확인합니다.
- **지금 업데이트**는 앱 파일 캐시만 지우고 다시 불러옵니다. 입력한 데이터(종목·매매·사유·사진)는 지워지지 않습니다.
- 새 버전을 낼 때(저장소 관리자용):
```bash
node tools/bump-version.js 1.3.0 "바뀐 점 1" "바뀐 점 2"
git add -A && git commit -m "v1.3.0" && git push
```
  `version.json`, `version.js`, `index.html`의 `?v=` 값이 함께 갱신됩니다. 이 단계를 빼면 사용자에게 새 버전 알림이 가지 않습니다.
