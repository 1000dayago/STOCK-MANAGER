# 주식 관리 (HTML 앱)

분할매수 순번별 손익·평단가·매도 시뮬레이션·백테스트를 PC/모바일에서 쓰는 순수 HTML/JS 앱입니다. 빌드 과정이 없고 GitHub Pages로 그대로 배포됩니다.

## 기능
- **홈 탭**: 자산 요약, 종목 카드(순번 요약), 현재가 한 번에 입력(입력일 표시), 다가오는 일정, 최근 매매, 종목 비중
- **매매 사유 에디터**: 매수 순번·매도 기록·종목마다 글쓰기 (글꼴/크기/굵게/색/형광펜/정렬/목록/표/링크/템플릿, 사진 여러 장), 매매 일지로 복기, 인쇄/PDF
- 종목 일정(실적 발표·배당 등), 바로가기 링크(설정에서 수정), 액면분할 조정
- 종목마다 탭, 매수할 때마다 순번(1번, 2번…) 기록 · 수정/삭제 · 분할/병합(병합 취소 가능)
- 전체 평단가, 순번별 수익률, 해외주식은 매수/매도 환율 반영(달러·원화 동시 표시)
- 매도/시뮬레이션: 순번을 직접 골라 수량 지정, 선입선출/고가순/저가순/평단 비례 비교, 수수료·세금 자동 계산
- 손익 보기: 월별·연도별·종목별·기간 합계, 해외 양도세 추정, 평가손익
- 평단가 계산기, 목표 평단 역산, 손익분기 매도가
- 백테스트: CSV 불러오기, 조건 자유 조합(거래량·이동평균·볼린저·RSI·MACD·신고가·등락률·렌코·분할매수·트레일링·외국인/기관 수급), 전략 저장·비교, 기간 분할 검증, 단순 보유와 비교
- Firebase 동기화(Google/이메일 로그인) + JSON 백업

## 관심 종목 · 가상 매매 · 시뮬레이션
- 종목 화면의 `보유 | 관심` 전환: 관심 종목에 목표 매수가와 메모, 목표가까지의 거리, 홈 카드
- **가상 매매**: 관심·보유 종목 모두에서 가상 매수/매도(실제 매매와 분리 저장). 입력 시점 기준 **사전 기록 / 사후 입력** 구분 표시, 가상 손익·승률, 날짜의 종가 자동 채우기, 실제 매수로 전환
- **분할 매수 계획**: 가격별 단계의 누적 평단·필요 금액·손익분기, 단계별 가상/실제 매수로 반영
- **시뮬레이션** 메뉴(구 백테스트): 종목 선택·가격 데이터 연결, 가상 매매 현황, 가상 매매 vs 백테스트 비교
- 관심 종목은 자동 수집(공개 저장소)에 종목별로 직접 켠 것만 포함됩니다.

## 화면 구성
- 휴대폰: 하단 메뉴 / 태블릿: 좁은 사이드바 / PC(1000px 이상): 펼친 사이드바(접기 버튼, 선택은 기억)

## 자동 수집 (공시 · 뉴스 · 재무 · 일봉 시세, 국내 종목)
GitHub Actions(`.github/workflows/collect.yml`)가 평일 저녁 7시(한국시간)에 `tools/collect.js`를 실행해 `data/`에 저장하고, 앱이 그 파일을 읽습니다.
- 필요한 키(저장소 Settings › Secrets and variables › Actions): `DATA_GO_KR_KEY`(공공데이터포털 일반 인증키, “금융위원회_주식시세정보” 활용신청), `DART_API_KEY`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`. 일부만 있어도 됩니다.
- 수집 대상은 `data/watchlist.json` (앱 설정 › 자동 수집에서 목록을 복사할 수 있습니다). **저장소가 공개이면 이 목록과 수집 결과는 누구에게나 보입니다.**
- 직접 실행: Actions 탭 › 자료 수집 › Run workflow. 결과는 `data/status.json`에 성공/오류로 기록됩니다.
- 테스트: `node tests/collect.test.js` (가짜 API 응답 사용)

## 배포 (GitHub Pages)
1. 이 폴더의 파일을 공개 저장소에 올립니다.
2. 저장소 Settings → Pages → Source: `main` 브랜치, `/ (root)`.
3. `https://아이디.github.io/저장소이름/` 주소로 접속 → 휴대폰은 “홈 화면에 추가”.

## Firebase 준비
앱의 **설정 화면 → “Firebase 준비 방법”** 에 단계가 있습니다. 요약:
Authentication(Google, 이메일/비밀번호) 사용 → 승인된 도메인에 `아이디.github.io` 추가 → Firestore 생성 → `firestore.rules` 내용을 규칙에 게시 → 웹 앱 `firebaseConfig`를 앱 설정에 붙여 넣기.
**규칙을 게시하지 않으면 데이터가 보호되지 않습니다.**

## 버전과 업데이트
- 설정 화면과 홈 아래에 현재 버전이 표시되고, 설정의 **업데이트 확인**으로 최신 여부를 확인합니다. 앱을 열 때와 앱으로 돌아올 때도 6시간마다 자동 확인하며, 새 버전이 있으면 화면 위에 알림이 뜹니다.
- **지금 업데이트**는 앱 파일 캐시만 지우고 다시 불러옵니다. 입력한 데이터(종목·매매·사유·사진)는 지워지지 않습니다.
- 새 버전을 낼 때(저장소 관리자용):
```bash
node tools/bump-version.js 1.3.0 "바뀐 점 1" "바뀐 점 2"
git add -A && git commit -m "v1.3.0" && git push
```
  `version.json`, `version.js`, `index.html`의 `?v=` 값이 함께 갱신됩니다. 이 단계를 빼면 사용자에게 새 버전 알림이 가지 않습니다.
